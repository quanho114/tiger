# V08 - Menu and Food Safety Retrieval Report

Status: DONE

## Scope and dependencies

Assigned task: V08. Delivers verified menu catalog retrieval and the food-safety domain boundary for Concierge V2. Connects to authoritative catalog data in PostgreSQL (`public.menu_items`, `public.categories`), applies strict availability, ordering mode, budget, and customer constraint filtering, evaluates allergen and cross-contact safety using kitchen audit verification and prompt-injection sanitization, and returns 5–8 bounded candidates conforming to shared Zod contracts.
Dependencies: V01 (DONE).
Scope boundary: No runtime routing edits, no modification of `runtime.ts` or public API handlers, no parallel pricing engine, no alteration of existing order/quote checkout logic.

## Changes

- Added `supabase/functions/_shared/concierge/food-safety.ts`:
  - `evaluateFoodSafety(item, customerAllergies, profile)`:
    - Strictly enforces fail-closed allergen evaluation.
    - Missing allergen profile or unverified kitchen audit (`verified_by_kitchen: false`) CANNOT yield `verified_safe`; returns `allergen_unverified` or `allergen_unknown` with `staff_confirmation_required = true`.
    - Confirmed presence returns `contains_allergen` with `staff_confirmation_required = true`.
    - Cross-contact risk or `may_contain` status returns `cross_contact_risk` with `staff_confirmation_required = true`.
    - Contradiction between catalog text/tags and kitchen profile (e.g. text mentions shrimp but profile claims absent) returns `conflict` with `staff_confirmation_required = true`.
    - Only kitchen-verified profiles (`verified_by_kitchen: true`) with cleared allergens yield `verified_safe` with `verified_at` timestamp.
  - `sanitizeCatalogText(text)`:
    - Strips control characters (`\x00-\x1F`), HTML script tags, general markup, markdown links, and prompt injection patterns (`SYSTEM INSTRUCTION`, `IGNORE ALL PREVIOUS INSTRUCTIONS`).
    - Enforces 500-character ceiling to defend downstream LLM context.
  - `normalizeAllergen(input)`:
    - Standardizes multilingual customer allergy terminology (Vietnamese and English) into canonical `AllergenType` tokens (`seafood`, `peanuts`, `eggs`, `dairy`, `gluten`, `soy`, `sesame`).
  - `checkAllergenConflict(item, allergen, profile)`:
    - Regex pattern matching against item name, description, and tags to detect contradictions with kitchen profiles.
  - `isItemSafeForRecommendation(evaluation)`:
    - Guard helper preventing items with `contains_allergen` or `conflict` states from entering AI recommendation candidates.
- Added `supabase/functions/_shared/concierge/menu-retrieval.ts`:
  - `fetchAuthoritativeCatalog(pool)`:
    - Executes flat, non-correlated SQL against `public.menu_items` joined with `public.categories` for published items.
    - Preserves authoritative `price_vnd`, `available`, `allow_dine_in`, `allow_delivery`, `serving_size`, `spice_level`, `is_signature`, and `tags`.
  - `retrieveMenuCandidates(poolOrCatalog, query)`:
    - Accepts PostgreSQL pool or in-memory catalog array (for deterministic testing).
    - Applies hard filters first: availability (`is_available = true`), ordering mode (`allow_dine_in`, `allow_delivery`), spice level ceiling, customer dislikes, and customer allergies.
    - Enforces fail-closed allergy exclusion: items containing requested customer allergens or with conflict states are strictly excluded.
    - Scores and ranks candidates by text similarity, category match, signature boost, and safety status.
    - Bounds results to 5–8 candidates (default 8, configurable limit 1–8).
    - Sets `staff_confirmation_required` globally if any candidate requires kitchen verification.
    - Validates output structure against `ConciergeV2MenuRetrievalResultSchema` via Zod before returning.
- Updated `supabase/functions/_shared/concierge/knowledge.ts`:
  - Added optional `verified_at` ISO string field to `ItemAllergenProfile`.
  - Added `getKnowledgeCacheEpoch()` and `invalidateKnowledgeCache()` helpers for cache coordination on admin updates.
- Updated `supabase/functions/_shared/contracts/concierge-v2.ts`:
  - Updated `UuidSchema` to standard RFC 4122 regex `/^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$/` ensuring full compatibility with PostgreSQL 128-bit UUID representations including sequential seed identifiers.
- Added `tests/server/concierge-menu-retrieval-contract.test.ts`:
  - 14 unit/contract tests covering prompt injection sanitization, allergen normalization, food safety state evaluation, fail-closed verification guarantees, conflict detection, empty catalog handling, availability/mode filtering, hard allergy exclusion, candidate bounding, and price stability.
- Added `tests/integration/concierge-menu-retrieval.test.ts`:
  - 4 real PostgreSQL database integration tests guarded by `assertIsolatedTestDatabase(pool)` verifying live catalog queries, bounded candidate retrieval against seed menu data, real-item food safety filtering, and immediate reflection of database price modifications without stale caching.
