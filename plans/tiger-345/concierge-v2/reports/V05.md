# V05 - Memory Schema, Settings and Repository Report

Status: DONE

## Scope and dependencies

Assigned task: V05. Consumes V01 contracts and owns the additive PostgreSQL schema for customer memory settings, compact food facts, and value-free behavioral suppressions, along with the actor-bound repository implementation and tests.
Dependencies: V01 (DONE).
Scope boundary: No catalog migration, no runtime routing edits, no modification of `runtime.ts` or public API handlers, no changes to the account deletion worker (owned by V15).

## Changes

- Added `supabase/migrations/20260922000001_concierge_v2_memory.sql`:
  - `public.user_ai_memory_settings`: Lazy-initialized, disabled-by-default customer preferences with `consent_version` (1–10000), `memory_epoch` (non-negative integer), and timestamps.
  - `public.user_ai_memories`: Owner-scoped compact food facts with `memory_type` (`preference`, `dislike`, `allergy`), normalized kebab-case `memory_key` (max 80 chars), strict single-property JSONB value `{"food": "..."}` (1–120 trimmed chars), `source` (`explicit`, `order_history`), `confidence` (0–100), `observed_at`, optional `expires_at`, and `schema_version = 1`. Unique compound key on `(user_id, memory_type, memory_key, source)` ensures independent coexistence of explicit and order-derived records.
  - `public.user_ai_memory_suppressions`: Records behavioral regeneration blocks on `(user_id, memory_type, memory_key, source)` containing only the fact key and `memory_epoch`. Stores zero value or food payload, preventing deleted memory retention.
  - Partial indexes: `user_ai_memories_owner_active_idx` for active unexpired facts, `user_ai_memories_owner_expiry_idx` for expiring facts, and `user_ai_memory_suppressions_owner_idx`.
  - Row-Level Security: Enabled on all three tables. Direct `INSERT`, `UPDATE`, and `DELETE` revoked from `PUBLIC`, `anon`, and `authenticated`. Authenticated customers have `SELECT` policies restricted to `auth.uid() = user_id`.
  - `SECURITY DEFINER` database functions:
    - `public.concierge_v2_memory_account_is_active(uuid)`: Validates that the customer profile exists without a deletion request, has no tombstone row in `public.customer_tombstones`, and has no active account deletion job (`status <> 'cancelled'`).
    - `public.concierge_v2_memory_settings_dto(uuid)`: Returns current settings JSON DTO.
    - `public.concierge_v2_set_memory_enabled(uuid, boolean, integer)`: Toggles enablement; disabling wipes durable facts/suppressions and increments `memory_epoch`.
    - `public.concierge_v2_forget_all_memory(uuid)`: Atomic forget operation that deletes facts and suppressions, disables settings, and increments `memory_epoch`.
    - `public.concierge_v2_write_memory_fact(uuid, integer, text, text, jsonb, text, smallint, timestamptz, timestamptz, smallint)`: Validates active account, enabled status, matching expected `memory_epoch`, absence of behavioral suppression for order-history source, fact shape, and per-user limits (100 facts) before source-scoped upsert.
    - `public.concierge_v2_delete_memory_fact(uuid, text, text, text)`: Deletes fact; creates value-free suppression record when deleting an `order_history` fact.
    - `public.concierge_v2_restore_behavioral_memory_fact(uuid, text, text)`: Removes behavioral suppression to allow re-aggregation.
    - `public.concierge_v2_purge_memory_for_deletion(uuid)`: Complete memory purge utility prepared for V15 deletion worker integration.
- Updated `supabase/functions/_shared/contracts/concierge-v2.ts`:
  - Added Zod schemas and TypeScript types: `ConciergeV2MemoryTypeSchema`, `ConciergeV2MemorySourceSchema`, `ConciergeV2MemoryFactInputSchema`, `ConciergeV2MemoryFactSchema`, `ConciergeV2MemorySettingsSchema`, `ConciergeV2MemorySettingsInputSchema`, `ConciergeV2MemoryWriteInputSchema`, `ConciergeV2MemoryFactSelectorSchema`, `ConciergeV2BehavioralMemorySelectorSchema`, `ConciergeV2MemoryFailureReasonSchema`, and operation envelope schemas.
  - Defined `ConciergeV2MemoryRepository` interface bound to verified customer actor without caller-supplied user ID parameters.
- Added `supabase/functions/_shared/concierge/memory-repository.ts`:
  - Implements `ConciergeV2MemoryRepository` with actor verification (`requireVerifiedCustomer`), mapping calls to PostgreSQL RPC functions and owner SELECT queries.
  - Public operations (`getSettings`, `setEnabled`, `listFacts`, `writeFact`, `deleteFact`, `forgetAll`, `restoreBehavioralFact`) use typed parameters and narrow database rows via `unknown` with strict Zod parsing.
  - Storage failures map to `{ ok: false, reason: 'MEMORY_STORAGE_UNAVAILABLE' }` or throw on list/get failures, preventing empty arrays from masquerading as successful empty results.
- Added `tests/server/concierge-memory-contract.test.ts`:
  - Verifies contract validation for compact food facts, owner ID omission from public DTOs, rejection of unknown fields (`raw_utterance`, `diagnosis`, `model_output`, oversized food), key formatting, and default settings state.
- Added `tests/policies/concierge-memory.test.ts`:
  - Real PostgreSQL RLS tests guarded by `assertIsolatedTestDatabase(pool)`.
  - Verifies anon access denial, owner-only read isolation, cross-customer record invisibility, and rejection of direct client `INSERT` and `DELETE` mutations even by the record owner.
- Added `tests/integration/concierge-memory.test.ts`:
  - Real PostgreSQL repository integration tests guarded by `assertIsolatedTestDatabase(pool)` and fixture accounts.
  - Verifies disabled-by-default behavior, explicit and order-history source coexistence, malformed and oversized fact rejection, epoch fencing after `forgetAll` and disable, value-free behavioral suppression and unsuppression, and write denial for tombstoned or deleting customer profiles.

No catalog code, no runtime session routing, no frontend state, no checkout/payment logic, no production data, and no credentials were changed.
