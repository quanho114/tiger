# V11 - Draft Cart Domain and Atomic Operations Report

Status: DONE

## Scope and dependencies

Assigned task: V11. Delivers the deterministic draft cart domain layer and atomic turn batching over the shared ephemeral session store for Concierge V2.
Dependencies: V02 (session store and CAS operations), V08 (authoritative catalog pricing and food-safety evaluations).
Scope boundary: No edits to `runtime.ts`, no direct cart writes (owned by V13), and no UI component edits (owned by V14).

## Changes

- Added `supabase/functions/_shared/concierge/draft-cart.ts`:
  - `createInitialDraft(overrides)`: Creates a clean draft instance conforming strictly to `ConciergeV2DraftSchema`, initializing with `version: 1`, `review_state: 'building'`, empty items, empty blocked items, `subtotal_vnd: 0`, and `exported_version: null`.
  - `calculateDraftSubtotal(items)`: Computes subtotal strictly in non-negative integer VND using `Math.max(0, Math.floor(price)) * quantity`.
  - `normalizeNote(note)`: Strips whitespace, normalizes null/undefined to empty string, and caps note length at 250 characters.
  - `applySingleDraftOperation(draft, rawOperation, catalogResolver, allowedPendingSuggestionIds, customerAllergies)`:
    - Validates operations through `ConciergeV2DraftOperationSchema`.
    - `add_item`:
      - Validates `pending_suggestion_id` against active session suggestions; returns `AMBIGUOUS_ACCEPTANCE` if unapproved or missing.
      - Resolves item from authoritative catalog via `catalogResolver`. Rejects unavailable items with `ITEM_UNAVAILABLE`.
      - Evaluates food safety: rejects items with allergen conflicts or unverified safety when customer has allergies with `ALLERGY_UNVERIFIED`.
      - Strictly derives price from `catalogItem.price_vnd` and ignores any external or model-provided price.
      - Enforces stable `(menu_item_id, note)` line identity: adding identical item and normalized note preserves existing `line_id` and increments quantity (clamped to 99). Distinct notes generate separate lines.
      - Enforces 30-line maximum limit on draft; returns `DRAFT_LINE_LIMIT_EXCEEDED` if exceeded.
      - Recalculates `subtotal_vnd` and advances `version`. Reverts `review_state` back to `'building'`.
    - `remove_item`:
      - Removes line from `items` and `blocked_items` by `line_id`.
      - Idempotent: non-existent line ID succeeds without error.
      - Recalculates `subtotal_vnd` and advances `version`.
    - `set_quantity`:
      - Updates quantity on existing line between 1 and 99.
      - Validates that quantity cannot be <= 0 (removals must use `remove_item`).
      - Recalculates `subtotal_vnd` and advances `version`.
    - `start_new_set`:
      - Clears all items and blocked items, creates new `draft_id`, sets `subtotal_vnd: 0`, reverts `review_state: 'building'`, and increments `version`.
  - `applyDraftBatch(initialDraft, operations, catalogResolver, allowedPendingSuggestionIds, customerAllergies)`:
    - Sequentially executes a batch of draft operations in an immutable pipeline.
  - `revalidateDraftAgainstCatalog(draft, catalogResolver, customerAllergies)`:
    - Inspects existing draft lines against current catalog state.
    - If price changed: moves line to `blocked_items` with reason `'PRICE_CHANGED'`.
    - If item unavailable: moves line to `blocked_items` with reason `'ITEM_UNAVAILABLE'`.
    - If safety compromised: moves line to `blocked_items` with reason `'ALLERGY_UNVERIFIED'`.
    - Updates `subtotal_vnd` and increments `version` if changes occurred.
  - `transitionDraftReviewState(draft, targetState)`:
    - `'ready_for_review'`: Requires `items.length > 0` and `blocked_items.length === 0`. Returns `INVALID_HANDOFF` if empty or blocked item reason if unresolved.
    - `'exported'`: Sets `exported_version = draft.version` and advances draft version.
  - `checkDraftHandoffEligibility(draft)`:
    - Verifies draft presence, non-empty items, zero blocked items, and that `review_state === 'ready_for_review'`.
  - `applyDraftTurnToSession(input)`:
    - Integrates with `sessionStore.compareAndSwap` for atomic turn batching.
    - Idempotency replay check: If `requestId` matches stored turn and `operationHash` matches, immediately returns `{ replay: true, record, turnResult }` without re-applying mutations.
    - If `requestId` matches but `operationHash` differs, returns `IDEMPOTENCY_MISMATCH`.
    - If `expectedStateVersion` is stale or concurrent CAS fails, returns `STATE_CONFLICT`.
    - Validates and applies draft batch; updates session record with new draft, pending suggestion IDs, and stores the turn result for idempotency.
- Added `tests/server/concierge-draft-cart.test.ts`:
  - 27 server unit, contract, and concurrency tests covering all subtasks and exit criteria:
    - Initial draft creation and non-negative integer VND subtotal calculation.
    - Note normalization and 250-character ceiling.
    - Stable item+note identity: same item and note increments quantity on existing line.
    - Distinct notes creating separate lines for identical menu item ID.
    - 30-line ceiling enforcement (`DRAFT_LINE_LIMIT_EXCEEDED`).
    - Bounded quantities [1, 99] and rejection of out-of-range quantities (`INVALID_DRAFT_OPERATION`).
    - Quantity updates via `set_quantity` and removal via `remove_item`.
    - Fresh draft instantiation via `start_new_set`.
    - Suggestions separation: suggestions alone create no lines in session draft.
    - Unapproved suggestions rejected with `AMBIGUOUS_ACCEPTANCE`.
    - Grounded catalog pricing (model prices rejected).
    - Unavailable items rejected with `ITEM_UNAVAILABLE`.
    - Unsafe items rejected with `ALLERGY_UNVERIFIED`.
    - Batch operation pipeline execution.
    - Catalog revalidation: moving items to `blocked_items` when price changes or item becomes unavailable.
    - Review state transitions and handoff eligibility checks.
    - Modifying draft reverting review state to `building`.
    - Exported version tracking.
    - Exit Criterion 1: Adding twice with same request ID applies once (idempotent replay).
    - Request ID collision with different operation hash returning `IDEMPOTENCY_MISMATCH`.
    - Exit Criterion 2: Conflicting state updates failing with `STATE_CONFLICT`.
    - Exit Criteria 3 & 4: Unsafe or unavailable items rejected with session state unmutated, and suggestions alone creating zero lines.
