# V02 - Shared TTL Session Store Report

Status: BLOCKED

## Scope and dependencies

V02 consumes the V01 Concierge V2 contract and owns the shared TTL session-store implementation, Upstash REST adapter, isolated unit tests, and real-store integration gate. It does not redirect `runtime.ts`, `public-api/index.ts`, `state-machine.ts`, or legacy persistence.

## Changes

- Added `supabase/functions/_shared/concierge/session-store.ts`, which implements create/read/CAS/delete behind `ConciergeV2SessionStore`. It creates opaque capabilities server-side, persists SHA-256 hashes only, binds authenticated identity, applies 45-minute idle and four-hour absolute expiry, keeps state in one bounded record, and returns safe domain errors for expiry, ownership, conflicts, idempotency mismatch, and unavailable storage.
- Added `supabase/functions/_shared/concierge/session-store-redis.ts`, an HTTPS-only Upstash Redis REST adapter. Redis scripts atomically validate expiry, capability hash, actor, idempotency, and state version before write/delete. The Redis key retains its original absolute TTL; accepted activity can only move idle expiry up to the immutable absolute expiry. Missing, malformed, transport-failed, or malformed-response storage maps through the store to `DEPENDENCY_UNAVAILABLE` without exposing configuration values.
- Added `tests/server/concierge-session-store.test.ts` for deterministic in-memory lifecycle, cross-store actor binding, non-revival after idle expiry, concurrent CAS, idempotent response-loss replay, idempotency mismatch, owned deletion, and unavailable-store behavior.
- Added `tests/server/concierge-session-store-redis.test.ts` for HTTPS/config rejection, Redis pipeline/script serialization, fixed absolute key TTL, idle-expiry capping, and safe adapter failure behavior.
- Added `tests/integration/concierge-session-store.test.ts`. It runs only with `CONCIERGE_REDIS_TESTS=1` and an isolated `CONCIERGE_REDIS_TEST_PREFIX` matching `concierge-v2-test:<run-id>`; cleanup deletes only session IDs created by that run. It contains real-store cross-client, simultaneous-CAS, response-loss replay, and owned-deletion assertions.

No SQL persistence, frontend/browser storage, runtime routing, feature flag, deployment, production data, credentials, paid evaluation, commit, or push changed.
