## Changes

- `runtime-v2.ts` authenticates capabilities/identity through SessionStore and runs
  legacy chat logic against a request-local working state. Conversation/proposal reads,
  transitions and raw-event writes never reach SQL or global fallback Maps in V2.
  The entire next state and response publish through one CAS. All pending fields and
  recommendation proposals survive requests; reset invalidates the old capability.
- `public-api/index.ts` negotiates body `protocol_version` or header
  `x-concierge-protocol-version`. Disabled V2 returns 400 `UNSUPPORTED_VERSION`;
  legacy chat/action/feedback under enabled V2 return 409 `REFRESH_REQUIRED`.
  JSON and SSE `complete` contain the same raw V2 completion schema (not the V1
  `data` wrapper). SSE does not announce success before CAS. Missing store returns
  503 and never falls back to SQL. Flag-read failures also fail closed.
- V2 accepts explicit reset and proposal-feedback actions. Draft operations are
  rejected until their owning tasks implement them. The temporary legacy bridge
  allows only menu/recommendation/FAQ tool execution; direct order submission,
  checkout and reservation confirmation cannot enter through legacy V2 cards.
  Existing reservation transactions remain on their explicit existing endpoints;
  their regression suites and pending-state preservation are tested.
- Guest feedback validates ownership against the proposal first, then stores only
  a daily rating count. No text, proposal/session ID, user ID or IP-derived scope is
  stored in the aggregate. The duplicate raw SQL writer in runtime now uses the same
  feedback service. V2 feedback resolves proposals from the ephemeral record. Its
  SQL transaction rolls back for a losing/replayed CAS to prevent duplicate counts.
- Additive migrations create the anonymous aggregate table and the previously missing
  server-only `system_settings` table. Both have RLS and no anon/customer privileges.
- Retention uses actual schema columns, inventories authenticated records separately,
  defaults to batches of 100 and rejects unsafe limits. See `../legacy-cleanup.md`
  for FK, auth-deletion, backup and rollback implications.
- Redis now preserves canonical JSON (including empty arrays) through real Lua CAS,
  handles null guest identity, round-trips/clears optional mutable fields, checks
  the version of the prepared candidate and retains the key's absolute TTL.
  A stale read no longer deletes a session concurrently refreshed by another request.
- V06 recognizes anchored declarations instead of matching positive fragments inside
  negations; multi-allergen declarations retain distinct facts. V08 requires explicit
  `absent` evidence and explicit no-cross-contact evidence before allergy-safe results.
- Memory schema extension now works with both Node's Zod 4 and Edge's Zod 3. This
  fixed an actual Edge startup failure exposed by HTTP smoke tests.
- Test fixtures now freeze reservation dates, replay identical order notes, use an
  authenticated customer for durable feedback review, provide settings OCC versions,
  and create isolated tables for schema constraint tests.

production deployment, production cleanup, or hosted Upstash account validation.
The local infrastructure evidence uses actual Redis 7 and verified HTTPS with an
ephemeral trusted certificate, through an Upstash-compatible test bridge. It does
not claim that production credentials/service provisioning have been validated.

V09/V10 still own context limits and full grounded orchestration. V04 owns the new
client envelopes and session lifecycle. V12-V18 remain separate acceptance/release
work. Feedback counters are metrics, not distributed business transactions: a process
crash after Redis CAS but before SQL COMMIT can lose a feedback sample; it cannot
create an order or persist a transcript.

## Rollback

Use the V2 kill-switch while keeping legacy writers rejected, as described in
`../legacy-cleanup.md`. Do not revert to SQL transcripts. Leave additive tables in
place; they have no business-data dependency. No production changes to undo.

## Handoff

- V04 consumes raw V2 envelopes and the new reset/feedback action variants in the
  shared contract. Never persist the capability on the browser.
- V10 can replace the read-only legacy bridge without changing SessionStore ownership,
  CAS, expiry, idempotency or the zero-SQL-transcript contract.
- `node scripts/test-concierge-redis.mjs [test-file ...]` provisions its own disposable
  Redis/HTTPS bridge, runs integration tests, and cleans up only its own resources.
  It requires Docker, OpenSSL and an already provisioned isolated PostgreSQL database.
