## Findings and remediation

- Intent parsing could mutate a draft for a question, unparsed quantity or dish
  name embedded in another word. `draft-intent.ts` now clarifies these inputs;
  five regressions failed before the fix and pass afterward.
- Memory edit/delete could omit the displayed consent epoch. Customer handlers
  now require it, the UI supplies it, and real PostgreSQL tests verify missing
  epoch -> 400, stale edit/delete -> 409, current edit -> 200 after forget/re-enable.
  Malformed input becomes a sanitized validation response.
- Capability and Redis CAS allegations were withdrawn after reviewing bearer
  verification and both version comparisons. Unknown allergies remain fail-closed;
  explicit draft review remains mandatory before handoff.
- Note forwarding and pending suggestion validation already existed in supplied
  code. The final model labeled these resolved; no new patch was needed for them.
- Full integration rerun exposed wall-clock-dependent restaurant fixtures after
  22:30. Transaction fixture hours now cover the full day, including restaurant
  and delivery services. Production business-hours logic was not modified.
