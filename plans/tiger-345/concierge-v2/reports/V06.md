# V06 - Explicit Memory Extractor Report

Status: DONE

## Scope and dependencies

Assigned task: V06. Consumes V05 memory repository and contracts, implementing deterministic explicit fact extraction, food text sanitization, stable slug generation, temporary/third-party/inquiry rejection, and atomic epoch-fenced persistence.
Dependencies: V05 (DONE).
Scope boundary: No modification to public routing (`public-api/index.ts`), no edits to `runtime.ts` (owned by integration steps V03/V10), no behavioral order-history aggregation (owned by V07), and no customer UI or account deletion wiring (owned by V15).

## Changes

- Added `supabase/functions/_shared/concierge/memory-extractor.ts`:
  - `cleanFoodText`: Strips script tags, HTML tags, prompt injection tokens, and PII. Recursively removes Vietnamese conversational particles and punctuation, enforces character boundaries, and normalizes capitalization. Rejects redacted PII inputs.
  - `slugifyFoodKey`: Normalizes food names by decomposing Vietnamese diacritics into stable kebab-case slugs adhering to `ConciergeV2MemoryKeySchema` (max 16 segments, max 80 characters). Normalizes recognized allergens to canonical keys (e.g. `seafood`, `peanuts`).
  - `extractExplicitFacts`: Pure deterministic rule-based extractor enforcing:
    - Quoted text rejection (`QUOTED_TEXT`).
    - Questions and menu inquiry rejection (`INQUIRY_OR_QUESTION`).
    - Temporary, time-bounded request rejection (`TEMPORARY_STATEMENT`) covering Vietnamese and English phrases (e.g., "hôm nay", "bữa này", "for now", "just for today").
    - Third-party preference rejection (`THIRD_PARTY_STATEMENT`) covering companions, colleagues, and family (e.g., "đi cùng bạn", "cho sếp", "for my friend").
    - Hypothetical/speculative rejection (`HYPOTHETICAL_OR_SPECULATIVE`).
    - Extraction of explicit allergies (`memory_type: 'allergy'`), explicit dislikes (`memory_type: 'dislike'`), and explicit preferences (`memory_type: 'preference'`).
    - Detection of explicit corrections (e.g., "mình ăn được hành rồi", "i can eat onions now") marked as `is_correction: true`.
    - Turn cap of at most 3 candidate facts per turn.
  - `processAndPersistExplicitMemory`: End-to-end extraction and persistence orchestrator:
    - Strictly checks customer authentication; guests and unauthenticated actors are rejected with `GUEST_OR_UNAUTHENTICATED` with zero persistence.
    - Reads customer settings and checks `enabled`; disabled customers are rejected with `MEMORY_DISABLED` with zero persistence.
    - Captures `memory_epoch` prior to extraction.
    - Extracts candidates via `extractExplicitFacts`.
    - Deletes target facts for detected corrections.
    - Persists new validated facts via `repository.writeFact` with `expected_memory_epoch = capturedEpoch`. If an epoch mismatch or disable occurs mid-flight, writes immediately halt and fail.
- Updated `supabase/functions/_shared/contracts/concierge-v2.ts`:
  - Added `ConciergeV2ExtractedFactCandidateSchema` and `ConciergeV2ExtractionResultSchema`.
- Updated `supabase/functions/_shared/concierge/food-safety.ts`:
  - Updated regexes to use Unicode boundaries `(?:^|[^\p{L}\p{N}])` and `(?:$|[^\p{L}\p{N}])` with the `/u` flag, ensuring Vietnamese compound characters are correctly matched without ASCII boundary failures.
- Added `tests/server/concierge-memory-extractor.test.ts`:
  - 20 unit and contract tests verifying diacritic slugification, allergen canonicalization, sanitization, PII redaction, preference/dislike/allergy extraction, correction parsing, temporary statement rejection, third-party rejection, hypothetical/question rejection, guest denial, disabled memory denial, and atomic epoch-race defeat.
- Added `tests/integration/concierge-memory-extractor.test.ts`:
  - 5 real PostgreSQL database integration tests guarded by `assertIsolatedTestDatabase(pool)` and test fixture accounts.
  - Verifies:
    1. Disabled memory blocks fact persistence in real database.
    2. Opted-in memory persists extracted facts with correct value objects and explicit source.
    3. Stale writes are defeated via `MEMORY_EPOCH_MISMATCH` when `forgetAll` is executed mid-flight.
    4. Corrections successfully remove prior constraints from `public.user_ai_memories`.
    5. Guest actors are strictly denied without database mutation.

No production data, credentials, public routing, or frontend state were modified.

## Rollback

Forward-only safe rollback: Extraction can be bypassed by returning `{ persisted: 0, rejection_reason: 'EXTRACTION_DISABLED' }` or disabling memory globally via feature flag. Existing facts remain safe in database.

## Handoff

- Callers in runtime orchestration (V09/V10) invoke `processAndPersistExplicitMemory({ message, actor, repository })` after customer turns.
- Guest actors should be checked beforehand or passed directly; the pipeline safely rejects non-authenticated actors without error.
- All extracted facts are validated against `ConciergeV2MemoryFactInputSchema` before writing.
