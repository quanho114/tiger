# V07 - Behavioral Aggregates and Selective Retrieval Report

Status: DONE

## Scope and dependencies

Assigned task: V07. Consumes V05 memory repository, V05 schema migrations, and contracts; implements:
1. Behavioral favorite aggregation from completed, paid order history within a 90-day window, distinguishing order frequency from quantity.
2. Value-free suppression handling preventing deleted behavioral favorites from reappearing upon subsequent aggregation runs.
3. Selective intent classification routing FAQ/operational queries away from personal-memory storage lookups (A08).
4. Conflict resolution and precedence hierarchy where dietary constraints (allergies, dislikes, and current session constraints) strictly defeat matching behavioral favorites.
5. Bounded compact facts (<= 12 facts, 200-400 tokens) with source tagging.
6. Graceful degradation when the memory repository is unavailable.

Dependencies: V05 (DONE).
Scope boundary: No modification to public routing (`public-api/index.ts`), no edits to `runtime.ts` (owned by integration steps V03/V10), and no customer UI or account deletion worker integration (owned by V15).

## Changes

- Added `supabase/functions/_shared/concierge/behavioral-memory.ts`:
  - `computeBehavioralCandidates`: Aggregates orders with `status = 'completed'` and `payment_status = 'paid'` from the last 90 days (`INTERVAL '90 days'`). Strictly excludes cancelled, unpaid, refunded, or test orders. Groups items and enforces that items must appear across at least 2 distinct orders (`HAVING count(DISTINCT o.id) >= 2`) to qualify as favorite candidates. Bounds candidate confidence between 70 and 85, strictly below explicit customer preferences (90) and allergies (100).
  - `aggregateBehavioralMemory`: Evaluates customer authentication and opt-in settings (`settings.enabled`). Computes candidates and persists qualified items into `public.user_ai_memories` using `source: 'order_history'` with a 90-day expiration window. Honors customer `memory_epoch` and suppresses items previously deleted by customer (`MEMORY_SUPPRESSED`).
- Added `supabase/functions/_shared/concierge/memory-retrieval.ts`:
  - `classifyMemoryIntent`: Classifies incoming messages into `faq` (operational questions regarding parking, opening hours, location, wifi, pet/smoking policies, and hotline) or `food_or_draft` (dishes, ingredients, suggestions, drinks, and orders).
  - `retrieveSelectiveMemory`:
    - A08 zero lookup: If message is classified as `faq`, returns zero facts with `fetched_from_storage: false` without reading from repository or storage.
    - Customer and opt-in verification: Guest actors and opted-out customers receive zero facts with `fetched_from_storage: false`.
    - Expiration filtering: Discards facts whose `expires_at` is in the past.
    - Conflict resolution: Reconciles preferences against allergies, dislikes, and current turn session constraints. Any favorite matching an allergy, dislike, or session constraint is defeated and eliminated.
    - Sorting and priority: Allergies take first priority, followed by dislikes, followed by explicit preferences, followed by order-history favorites sorted by confidence descending.
    - Bounded facts: Slices final facts to at most 12 items.
    - Prompt formatting: `formatMemoryPrompt` formats compact source-tagged lines (`[Dị ứng (tự khai)]`, `[Không thích (tự khai)]`, `[Yêu thích (tự khai)]`, `[Yêu thích (từ lịch sử gọi món)]`). Strictly excludes addresses, phones, customer names, prices, transcripts, or provider reasoning.
    - Graceful degradation: Catches repository errors and returns empty facts without crashing chat.
- Added `tests/server/concierge-memory-retrieval.test.ts`:
  - 11 unit and contract tests verifying:
    - Intent classification for operational/FAQ queries vs food/draft queries.
    - A08 zero repository calls on parking and operational FAQ questions.
    - Guest and opted-out customer exclusion.
    - Explicit dislike defeating matching behavioral favorites.
    - Current session constraints defeating matching behavioral favorites.
    - Explicit allergy priority over preferences.
    - Fact count and token bounding (<= 12 facts, <= 400 tokens, zero prohibited metadata).
    - Graceful degradation on repository failure.
- Added `tests/integration/concierge-behavioral-memory.test.ts`:
  - 3 real PostgreSQL integration tests guarded by `assertIsolatedTestDatabase(pool)` and test fixture accounts:
    1. Verifies 90-day window, completed + paid order requirement, exclusion of cancelled/unpaid/old orders, and >= 2 order frequency requirement.
    2. Verifies persistence into `public.user_ai_memories` with `source = 'order_history'`, suppression generation on deletion, and re-aggregation suppression adherence.
    3. End-to-end selective retrieval proving A08 zero lookup for parking queries and explicit dislike defeating matching favorite on food queries.

No production data, credentials, public routing, or frontend state were modified.

## Rollback

Forward-only safe rollback: Personalization retrieval can be disabled by returning `{ intent_type: 'faq', fetched_from_storage: false, facts: [], formatted_prompt: '', estimated_tokens: 0 }` in `retrieveSelectiveMemory` or via a feature flag. Generic recommendations remain fully operational.

## Handoff

- Downstream runtime orchestration (V09/V10) invokes `retrieveSelectiveMemory({ message, actor, repository, currentSessionConstraints })` when assembling model turn context.
- If the returned `fetched_from_storage` is `false`, the turn had no personal data retrieval (e.g. FAQ query, guest actor, or disabled memory).
- If `formatted_prompt` is non-empty, it is included in the model prompt under dietary/preference guidelines.
